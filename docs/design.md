# 个人网站设计说明

## 1. 文档信息

- 设计依据：已确认的 `docs/prd.md` `v1.0`
- 设计范围：个人网站单页信息架构与实现约束
- 技术边界：保留现有 Jekyll 与 `modern-resume-theme`，本阶段不修改网站实现
- 设计目标：让同学、教师、项目合作伙伴和实习 HR 在较短时间内形成“金融与技术复合、做事有方法、能够把研究和需求落实为结果”的印象

## 2. 设计原则

1. **真实可信**：只呈现 PRD 已确认的个人信息、技能、联系方式与项目事实，不补写未经确认的经历或能力等级。
2. **内容优先**：视觉服务于身份、能力与项目证据，避免装饰性大图、复杂动画和与内容无关的视觉噪声。
3. **单页顺读**：页面固定按 Hero、About、Skills、Projects、Contact 排列，主操作可直接跳转到目标区域。
4. **克制专业**：以中性背景、深色正文和蓝色强调色建立清晰、理性的学术与技术气质。
5. **移动优先可读**：在窄屏上保持自然堆叠、清晰字号、足够触控区域和无横向溢出。
6. **可验证**：关键内容、链接、响应式、隐私与部署配置均在 `docs/checklist.md` 中提供可见、可点击或可复现的验收方式。

## 3. 页面结构

页面为一个公开访问的单页站点，内容顺序不得调整：

### 3.1 Hero

- 首屏显示公开称呼“吕同学”。
- 主标题下显示一句话定位：“金融科技与区块链方向本科生，关注金融数据分析、业务原型开发与 AI 辅助项目实践。”
- 提供三个清晰操作：
  - “查看项目”：站内跳转到 `#projects`。
  - “访问 GitHub”：打开 <https://github.com/824man824-bit>。
  - “发送邮件”：打开 `mailto:fukun.lyu@audencia.com`。
- GitHub 使用新页面打开，并设置 `rel="noopener noreferrer"`；邮件链接不强制新开页面。
- Hero 不展示电话、出生日期、性别、政治面貌或未经确认的求职状态。

### 3.2 About

- 使用 PRD 第 6.2 节确认的真实简介，不扩写未经确认的经历。
- 桌面端采用头像与文字并列布局；头像位于左侧，正文位于右侧。
- 移动端改为头像在上、正文在下，头像居中。
- 补充呈现“金融科技、区块链、信息系统、金融与政策数据分析、业务系统原型开发”五个学习方向，可使用简洁标签，但不得伪装为能力评级。
- 头像必须使用可读替代文本“吕同学头像”。

### 3.3 Skills

- 按 PRD 既定的六类分组展示：编程基础、Web 与数据存储、数据分析、可视化与汇报、金融数据工具、AI 辅助工作。
- 桌面端可采用两列或三列技能分组卡片；移动端改为单列。
- 技能项使用文本标签或短列表，不使用百分比、星级、进度条等无法验证的熟练度表达。
- “Bloomberg Terminal”明确保留“基础使用”口径；`gretl` 拼写必须正确。

### 3.4 Projects

- 本期只展示“粤港澳大湾区低空经济产业孵化与区域攀比政策分析”一个项目。
- 项目区域采用一张主项目卡，信息按以下顺序组织：项目类型、研究问题、主要工作、技术与工具、可公开结果、表述边界。
- 用小型数据摘要突出 `345` 份政策文本、`2019—2024` 年数据范围和双向固定效应模型，但摘要必须与正文语义一致。
- 统计结果完整保留数值与限定条件，尤其是 `0.0026`、`p = 0.285`、`0.5012`、10% 显著性水平和人口规模在 1% 显著性水平上为负。
- 不设置虚假的“查看论文”“查看源码”或项目仓库按钮；未经单独授权，不公开论文全文、原始数据和源代码。
- 不采用与最终论文不一致的 Granger 检验、Panel VAR、131 条有效政策或企业新增注册数表述。

### 3.5 Contact

- 作为独立末尾区域显示 GitHub 与邮箱两个联系入口。
- GitHub 链接文字应说明目的，例如“访问 GitHub 主页”；邮箱链接文字应包含或紧邻公开邮箱地址。
- 两个入口均可通过键盘聚焦，并提供清晰可见的聚焦状态。
- 不添加联系表单、电话、即时聊天或需要后端处理的功能。

## 4. 视觉规范

### 4.1 色彩

浅色模式采用以下基础色：

| 用途 | 色值 | 使用方式 |
| --- | --- | --- |
| 页面背景 | `#FFFFFF` | 主背景 |
| 次级背景 | `#F7F9FC` | 技能分组、项目摘要或轻量卡片 |
| 主文本 | `#253044` | 标题与正文 |
| 次级文本 | `#5F6B7A` | 辅助说明与元信息 |
| 主强调色 | `#477DCA` | 主要链接、按钮与聚焦状态 |
| 强调色悬停 | `#355E98` | 链接与按钮的悬停/激活状态 |
| 分隔线 | `#D9DEE7` | 区域边界、卡片边框 |

深色模式保留主题现有能力，并调整为：

| 用途 | 色值 | 使用方式 |
| --- | --- | --- |
| 页面背景 | `#222222` | 主背景 |
| 次级背景 | `#2B2F36` | 卡片与分组背景 |
| 主文本 | `#E6E6E6` | 标题与正文 |
| 次级文本 | `#BCC5D0` | 辅助说明 |
| 主强调色 | `#8AB4F8` | 链接、按钮与聚焦状态 |
| 分隔线 | `#454B55` | 区域边界、卡片边框 |

颜色规则：

- 正文、链接、按钮在浅色和深色模式下均应清晰可读。
- 不以颜色作为唯一的信息区分方式；链接同时依靠文字、下划线、按钮轮廓或图标语义表达。
- 不引入紫色渐变、霓虹色或与现有专业语气冲突的高饱和装饰色。

### 4.2 字体

- 统一使用无衬线字体，不新增需要构建处理的大型字体依赖。
- 推荐字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", Roboto, Arial, sans-serif`。
- 中文优先使用系统可用的微软雅黑、苹方或思源黑体；英文与数字可由 Segoe UI 或 Roboto 呈现。
- 桌面端正文建议 `16–18px`、行高 `1.7`；移动端正文不小于 `16px`。
- 主标题桌面端建议 `48–56px`，移动端建议 `34–40px`；区域标题保持清晰层级，不仅依靠字号区别。

### 4.3 间距与形态

- 内容最大宽度建议 `1080px`，桌面端左右留白不少于 `24px`。
- 区域之间使用 `72–96px` 的垂直节奏；移动端缩减为 `48–64px`。
- 卡片圆角控制在 `10–14px`，使用细边框或轻阴影，不使用厚重拟物阴影。
- 可点击目标最小高度或宽度为 `44px`；聚焦轮廓不得被全局样式移除。
- 动画仅限短暂的颜色、边框或轻微位移过渡；检测到 `prefers-reduced-motion: reduce` 时关闭非必要动画与平滑滚动。

## 5. 响应式设计

- 主要检查宽度为桌面端 `1440 × 900` 与移动端 `375 × 812`，并补查约 `320px` 宽度下是否出现横向溢出。
- 复用主题现有 `767px` 响应式断点，必要时在 `_sass/modern-resume-theme.scss` 中增加局部规则，不引入新的前端框架。
- 移动端 Hero 操作按钮纵向排列或允许自然换行，按钮文字不得被截断。
- About 的头像与正文由并列变为单列；头像建议显示为 `144–160px`，不挤压正文。
- Skills 分组和项目数据摘要改为单列；长项目名、英文工具名和邮箱允许安全换行。
- Projects 正文不使用需要横向滚动的表格作为主要表达；数据结果使用可换行的文本或响应式摘要块。
- Contact 入口在窄屏下占据可点击的整行区域，邮箱不得超出视口。

## 6. 导航与交互

- 页面内部锚点至少使用 `#about`、`#skills`、`#projects`、`#contact`。
- “查看项目”必须跳转到 Projects；浏览器后退、键盘 Tab 和 Enter 操作不得失效。
- GitHub 外链在新页面打开；邮箱使用 `mailto:`。
- 所有链接均提供可见的默认、悬停、聚焦和激活状态。
- 若启用平滑滚动，应尊重减少动态效果的系统偏好，并避免标题被固定元素遮挡。

## 7. GitHub Pages 配置

实现阶段必须将站点配置为 GitHub Pages 项目站点：

```yaml
repository: 824man824-bit/personal-resume
url: https://824man824-bit.github.io
baseurl: /personal-resume
```

- 站内链接、样式、脚本和图片均使用 Jekyll 的 `relative_url` 或等效的 `site.baseurl` 安全写法。
- 预期公开地址为 `https://824man824-bit.github.io/personal-resume/`。
- 不将本地磁盘路径写入配置、页面、样式、图片引用或生成结果。

## 8. 文件职责与实施映射

| 文件 | 设计阶段定义的职责 |
| --- | --- |
| `_config.yml` | 写入固定的 repository、url、baseurl；提供 Hero、About、Skills、Projects、Contact 的已确认内容；移除模板人物、无关社交账号、电话与占位数据。 |
| `index.md` | 保持单页入口与 `default` 布局，不承载重复内容。 |
| `_layouts/default.html` | 固定页面渲染顺序，组织 Hero、About、Skills、Projects、Contact，保留语义化 `main` 与主题脚本加载。 |
| `_includes/header.html` | 从普通简历页眉调整为 Hero，渲染称呼、定位和三个主要操作。 |
| `_includes/about.html` | 渲染真实简介、学习方向与语义化头像 `<img>`；不得继续使用缺少替代文本的纯背景图作为头像。 |
| `_includes/section-list.html` | 承载 Projects 的结构化项目内容，必要时增加不破坏其他列表的语义类名。 |
| `_includes/section-text.html` | 承载 Skills 与 Contact 的 Markdown/HTML 内容，并保持标题层级与链接可访问性。 |
| `_includes/footer.html` | 显示简洁版权/署名与公开邮箱；关闭模板的 “References on request” 占位文案。 |
| `assets/main.scss` | 继续作为 Jekyll 样式入口，仅导入主题样式。 |
| `_sass/modern-resume-theme.scss` | 汇总本项目需要的 Hero、按钮、分组、项目卡、Contact 和响应式样式覆盖。 |
| `_sass/base.scss`、`_sass/type.scss`、`_sass/button.scss`、`_sass/dark.scss` | 分别维护基础布局、字体层级、交互按钮和深色模式；修改时保持职责单一。 |
| `assets/js/index.js` | 保留基于 `prefers-color-scheme` 的深色模式行为；除非验收发现必要问题，不增加复杂交互。 |
| `images/profile.webp` | 保存从用户已授权简历头像裁剪得到的网页图片，不包含原始简历页面或其他个人信息。 |
| `docs/prd.md` | 作为内容、事实、隐私和成功标准的需求来源。 |
| `docs/design.md` | 作为信息架构、视觉、响应式、文件职责和实现约束的设计来源。 |
| `docs/checklist.md` | 记录可见、可点击或可复现的验收项；只有取得证据后才能勾选。 |
| `docs/progress.md` | 记录每一阶段完成事项、文件、验证、用户决定、问题与下一步。 |

## 9. 图片来源与处理

- 唯一计划使用的人物图片来自用户已授权读取的中文简历证件照。
- 实现阶段只进行裁白边、居中、尺寸调整和网页压缩，不进行生成式重绘、美颜、换脸或未经确认的背景替换。
- 目标文件为 `images/profile.webp`；建议保留自然纵横比，最终显示不模糊且文件体积合理。
- 仓库中现有模板风景图、截图和测试图片不得作为个人内容图片使用。
- 不从网络抓取未经授权的个人照片、学校标志或项目插图；若未来需要新增图片，必须先确认来源、授权和公开范围。
- 头像使用真实 `<img>` 元素及 `alt="吕同学头像"`，不使用无法提供替代文本的纯 CSS 背景图。

## 10. 隐私与内容边界

- 可公开内容严格限定为 PRD 第 11.1 节列出的称呼、定位、简介、学习方向、技能、项目摘要、GitHub、邮箱和裁剪头像。
- 网站及仓库不得出现电话、出生日期、性别、政治面貌、本地磁盘路径、密码、邀请码、Token、API Key 或 `.env` 内容。
- 不上传未经确认的论文全文、原始数据、项目源代码或包含额外个人信息的原始简历文件。
- 项目统计结果必须保留样本、模型和显著性限定，不表述为普遍结论或确定因果。
- 外部链接只使用已确认的 GitHub 与邮箱；没有公开地址的论文和项目不显示占位链接。

## 11. 本阶段交付边界

- 本阶段只创建和更新 `docs/design.md`、`docs/checklist.md`、`docs/progress.md`。
- 不修改 `_config.yml`、布局、包含文件、样式、脚本、图片或任何网站实现文件。
- 不创建头像文件，不执行部署，不声明网站、移动端、深色模式、链接或构建已经通过验收。
