# 个人网站产品需求文档（PRD）

## 1. 文档信息

- 文档版本：`v1.0`
- 编写日期：2026-07-24
- 产品形态：基于现有 Jekyll `modern-resume-theme` 的个人展示网站
- 部署目标：GitHub Pages 项目站点
- 公开称呼：吕同学
- 文档状态：内容需求已根据用户确认整理，等待最终审阅

## 2. 产品背景

当前仓库仍是简历主题模板，姓名、标题、联系方式、项目和简介均为占位内容，尚不能代表网站所有者。网站需要在不更换现有 Jekyll 技术栈的前提下，形成一份真实、克制、可验证的个人介绍，帮助访客快速了解吕同学的学习方向、能力结构、代表项目和联系渠道。

## 3. 产品目标

建设一个面向同学、教师、项目合作伙伴和实习 HR 的个人网站，使访客能够在较短时间内完成以下认知：

1. 网站主人是谁，以及当前主要学习方向。
2. 具备哪些有事实依据的技术、数据分析和项目能力。
3. 完成过什么代表项目，具体采用了什么方法并得到什么结果。
4. 如何通过 GitHub 或邮箱进一步联系。

## 4. 目标访问者

### 4.1 同学

- 关注课程项目、技术栈和可交流的学习方向。
- 需要快速判断是否适合共同学习或组队完成项目。

### 4.2 教师

- 关注研究问题、方法选择、结果表达和学术边界。
- 需要确认项目描述是否严谨、是否能够追溯到真实成果。

### 4.3 项目合作伙伴

- 关注执行能力、数据处理能力、技术实现能力和协作方式。
- 需要快速了解可承担的工作类型和既往项目经验。

### 4.4 实习 HR

- 关注个人定位、能力结构、代表经历和联系方式。
- 需要在有限浏览时间内形成清晰、可信的候选人印象。

## 5. 希望留下的印象

网站应传达以下统一印象：

- 具备金融与技术相结合的复合学习背景。
- 做事有方法，能够拆解目标、数据、方法与结果。
- 能够把研究问题或业务需求落实为可检查的项目产出。
- 表达真实克制，明确区分统计关联、预测作用与因果关系。

不得将“基础使用”改写为“精通”，不得添加缺少项目或材料依据的技能。

### 7.4 Projects

本期只展示一个代表项目。

#### 项目名称

粤港澳大湾区低空经济产业孵化与区域攀比政策分析

#### 项目类型

中观经济学课程论文与配套数据分析项目。

#### 研究问题

分析粤港澳大湾区城市在低空经济赛道中的政策竞争特征，并检验多维政策信号与低空经济技术创新产出之间的关系。

#### 主要工作

- 整理并分析 345 份粤港澳大湾区低空经济政策文本。
- 使用大语言模型对扶持力度、监管强度、政策确定性和综合情感进行结构化量化。
- 将政策指标与 2019—2024 年城市专利及宏观面板数据进行匹配。
- 使用双向固定效应面板回归，控制城市经济发展水平、人口规模、科技财政支出、城市固定效应和年份固定效应。
- 使用 Python 完成数据采集、清洗、统计分析和可视化，并整理课程论文。

#### 技术与工具

- 数据采集：Python、requests、BeautifulSoup。
- 数据处理与统计：pandas、NumPy、SciPy、statsmodels。
- 文本量化：大语言模型辅助的多维政策情感评分。
- 可视化：Matplotlib、Seaborn。
- 成果整理：Word 课程论文及配套数据、代码和图表。

#### 可公开的主要结果

- 345 份政策的确定性均值为 73.8，扶持强度均值为 56.4，监管强度均值为 30.7。
- 扶持力度与综合情感分相关系数为 0.92；监管强度与综合情感分相关系数为 -0.70。
- 双向固定效应模型中，政策综合得分系数为 0.0026，`p = 0.285`，未显示显著的直接促进作用。
- 科技财政支出系数为 0.5012，在 10% 显著性水平上为正；人口规模的系数在 1% 显著性水平上为负。

#### 表述边界

- 页面必须表述为样本与模型中的统计结果，不得写成普遍适用的绝对结论。
- “政策综合得分不显著”不得改写为“政策没有作用”。
- 回归结果不得在缺少额外识别依据时表述为确定因果关系。
- 简历中有关 Granger 检验、Panel VAR、131 条有效政策及企业新增注册数的描述与最终课程论文不一致，本期网站不采用这些旧表述。
- 课程论文和本地项目目录只作为内部事实来源；本期不公开本地路径，也不默认上传论文全文、原始数据、代码或 `.env`。

## 9. 功能需求

### 9.1 导航与浏览

- 访客可以顺畅浏览 Hero、About、Skills、Projects、Contact。
- 页面内主要入口能够跳转到对应内容或外部链接。

### 9.2 外部链接

### 9.3 深色模式

- 保留主题已有的深色模式能力。
- 深色与浅色状态下均需保证文本、链接和按钮具有足够可读性。

## 10. 非功能需求

- 桌面端和移动端均不得出现明显横向溢出、内容遮挡或不可读字号。

### 10.2 可访问性

- 页面保持清晰的标题层级。
- 所有交互链接可通过键盘聚焦。
- 头像包含替代文本。
- 链接文字能够说明目的，不使用无上下文的“点击这里”。

### 10.3 性能与资源

- 头像经过合理裁剪与压缩。
- 不引入完成本期需求所不必要的大型前端依赖。
- GitHub Pages 上的 CSS、JavaScript、图片和站内链接路径正确。

### 10.4 内容真实性

- 所有个人信息来自用户确认或用户授权读取的简历。
- 项目事实以用户授权读取的最终课程论文为准。
- 对存在版本冲突的信息采用最终论文口径，并在内部文档保留差异说明。

2. 首屏在 30 秒内让同学、教师、项目合作伙伴和实习 HR 了解“吕同学”的学习方向、核心能力和代表项目。

7. 内容只使用用户确认的信息，不保留模板人物、示例项目或占位联系方式。

## 14. 验收方法

- 内容核对：逐项对照本 PRD、用户确认记录、简历和最终课程论文。
- 隐私核对：搜索页面输出和配置文件，确保禁止公开的信息不存在。
- 链接核对：检查 GitHub、邮箱和所有站内链接。
- 构建核对：执行可用的 Jekyll 构建流程并记录结果；如本机环境仍不可用，必须在 GitHub Pages 或可用 CI 环境完成验证。
- 响应式核对：至少检查一个桌面宽度和一个移动端宽度。
- 视觉核对：确认头像白边已去除，浅色与深色模式均可读。
- Git 核对：确认至少 4 次新的、有意义的作业提交，并确保提交主题与阶段工作一致。

- 网站不展示本地来源文件路径，内部文档也不得记录任何密钥内容。
